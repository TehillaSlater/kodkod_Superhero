# זירת קרבות של גיבורי-על

פרויקט Python שבו בוחרים גיבורי-על ומנהלים ביניהם קרב. עובדים עליו במקביל
בענפים נפרדים, וכל אחד אחראי לקובץ משלו כדי לצמצם התנגשויות במיזוג.

## חלוקת עבודה

- **ענף הגיבורים:** `heroes.py` — יצירת מאגר הגיבורים, בחירת גיבור ותצוגת
  הגיבורים ומצב החיים שלהם.
- **ענף הקרב:** `battle.py` — מנוע הקרב, מהלכים ואירועי הקרב.
- **נקודת התחלה וחיבור הפרויקט:** `main.py` — כרגע מכיל הודעת פתיחה פשוטה;
  לאחר ששני החלקים מוכנים, יחבר בין בחירת הגיבורים למנוע הקרב.

## חוזה הממשק

כל גיבור ייוצג במילון עם המפתחות והטיפוסים הבאים:

```python
{
    "name": str,
    "hp": int,
    "max_hp": int,
    "attack": int,
    "defense": int,
    "special_used": bool,
}
```

### הפונקציות ב-`heroes.py`

```python
choose_hero() -> dict
display_status(hero1: dict, hero2: dict) -> None
```

- `choose_hero()` תציג את הגיבורים הזמינים ותחזיר מילון של הגיבור שנבחר.
- `display_status(hero1, hero2)` תציג את מצב החיים של שני הגיבורים.

### הפונקציה ב-`battle.py`

```python
start_battle(hero1: dict, hero2: dict) -> str
```

- `start_battle(hero1, hero2)` תנהל את הקרב ותחזיר את שם המנצח.

יש לשמור על שמות הפונקציות, הפרמטרים ומבנה מילון הגיבור כפי שמוגדרים כאן.
כך ניתן לפתח ולבדוק כל חלק בנפרד, ואז לחבר אותם דרך `main.py`.

## עבודה בענפים ומיזוג

1. מתחילים מענף `main` המעודכן, ויוצרים לכל משימה ענף נפרד:

   ```bash
   git switch main
   git pull
   git switch -c feature/heroes
   ```

   עבור מנוע הקרב, יוצרים ענף נפרד בשם `feature/battle`.
2. כל אחד עובד ומבצע commit רק לקובץ שבאחריותו.
3. מעלים את הענף ל-GitHub ופותחים Pull Request אל `main`.
4. אחרי ששני החלקים מוזגו, מחברים אותם ובודקים את הפרויקט דרך `main.py`.
